# Retained lifecycle cache correction

The independent native-collision probe found an unbounded pre-correction retired-ID map that exhausted the Rhai object-map limit at distinct-lifetime index1009. Historical package folders and the previous four-package freeze are retained outside the distribution.

The gameplay definitions, health, attack patterns, objectives, prices, images and sounds are unchanged. A separate independent timing probe also found that changing the old warning-clock modulo at half-health could release a low-phase volley after only two ticks. Bosses now latch their phase and restart its warning clock on a phase transition, preserving the advertised full 14-tick telegraph. The actual World regression tests transition immediately after the second high-phase warning at every difficulty, including an old checkpoint lacking the latch. The script now stores a FIFO of at most 128 recent retired IDs, removes reused IDs on spawn before checking their health, and migrates pre-FIFO states into a deterministic bounded subset. Boss clocks absent from the new World's snapshot are discarded; live peer clocks remain intact.

The package-local retained-state proof checks real bundled Catalog activation and a test-only native stationary lethal projectile, 1,205 lives (1,200 unique plus five reused IDs), exact one-death rewards, current-lifecycle callback deduplication, nine JSON checkpoint/RNG roundtrips, old 960-ID cache migration and all four difficulty kills. Boss probes add 1,205 abandoned-live replays and simultaneous peer-clock preservation. This is a lifecycle stress proof, not a combat-balance shortcut. Normal mission acceptance and boss phase probes were rerun independently of this stress fixture.

A duplicate callback for an entity retired more than 128 deaths ago is outside the retained guard window; the engine emits each real death once and queued callbacks are not delayed across 128 later deaths. Reusing an ID through an actual spawn always starts a fresh guarded lifecycle.
